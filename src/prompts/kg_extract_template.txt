-Goal-
Given a text document, identify all entities and the relationships among them, then return the result as structured JSON.

You may extract up to {max_knowledge_triplets} entity-relationship pairs.

-Entity Types-
Use ONLY the following entity type categories.  If an entity does not fit any category, use "Other":
- Person:          Named individuals (real or fictional)
- Organization:    Companies, institutions, agencies, teams, groups
- Technology:      Programming languages, frameworks, tools, algorithms, standards
- Location:        Cities, countries, regions, buildings, landmarks
- Event:          Conferences, wars, incidents, milestones, releases
- Concept:        Theories, ideas, methods, disciplines, principles
- Document:        Papers, books, reports, patents, specifications
- Product:        Software, hardware, consumer goods, services
- Award:          Prizes, honors, certifications, rankings

-Steps-
1. Identify all entities in the text.  For each entity:
   - entity_name: Canonical, capitalized name.  Resolve pronouns ("she", "it", "they") and ambiguous references ("the company", "this method") to their full canonical name using prior context.
   - entity_type: One of the types listed above.
   - entity_description: A concise but comprehensive description of the entity's attributes and activities as described in the text.

2. From the entities identified in step 1, identify all pairs of (source_entity, target_entity) that have a meaningful relationship.  For each pair:
   - source_entity: Name exactly as listed in step 1.
   - target_entity: Name exactly as listed in step 1.
   - relation: A specific, descriptive verb phrase (e.g. "developed", "acquired", "was CEO of").  Avoid vague relations like "is related to", "is associated with", or "involves".
   - relationship_description: A brief explanation of why these entities are related, based on the text.

3. Output Formatting:
   - Return the result as valid JSON with two keys: "entities" (list of entity objects) and "relationships" (list of relationship objects).
   - Do NOT include any text, explanation, or markdown outside the JSON structure.
   - If no entities or relationships are found, return: {{ "entities": [], "relationships": [] }}

-Rules-
- Extract only entities and relationships that are explicitly stated or directly inferable from the text.  Do NOT fabricate or speculate.
- Merge duplicate entity references: if "Einstein" and "Albert Einstein" refer to the same entity, use "Albert Einstein" once.
- Prefer specific relations over generic ones: "invented" > "contributed to" > "is related to".
- Do NOT extract trivially generic relationships (e.g. "Entity A exists" or "Entity B is a concept").
